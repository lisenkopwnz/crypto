# Design Section

## Архитектурный обзор

Проект представляет собой REST API для получения и хранения курсов криптовалют с использованием внешнего источника данных (Deribit API). Архитектура построена по принципу чистой архитектуры (Clean Architecture) с разделением на слои:

- **Слой представления (API Layer)** — FastAPI эндпоинты, обработка HTTP запросов.
- **Слой бизнес-логики (UseCase Layer)** — сценарии использования системы.
- **Слой доступа к данным (Repository Layer)** — абстракция над базой данных.
- **Слой инфраструктуры** — адаптеры, внешние API, фоновые задачи.

Такое разделение позволяет легко тестировать, масштабировать и модифицировать каждый слой независимо.

---

## Структура проекта

Проект организован по принципу модульности:

- `app/api/v1/endpoints/` — обработчики HTTP запросов.
- `app/api/v1/usecase/` — сценарии использования.
- `app/api/v1/repositories/` — интерфейсы и абстракции для доступа к данным.
- `app/api/v1/adapters/` — реализации репозиториев.
- `app/api/v1/schemas/` — Pydantic модели для валидации и сериализации.
- `app/api/v1/models/` — SQLAlchemy ORM модели.
- `app/api/v1/services/` — вспомогательные сервисы и утилиты.
- `app/celery_app.py` — настройка Celery для фоновых задач.
- `app/main.py` — точка входа FastAPI приложения.

---

## Технологический стек

Проект использует следующие технологии:

- **FastAPI** — веб-фреймворк для создания REST API с автоматической документацией.
- **SQLAlchemy** — ORM для работы с базой данных.
- **Pydantic v2** — валидация данных и сериализация.
- **Celery** — обработка фоновых задач (сбор курсов).
- **Redis** — брокер сообщений для Celery.
- **Requests** — HTTP клиент для запросов к внешним API.
- **PostgreSQL** — база данных для хранения исторических данных.

## Основные компоненты

### API слой (Endpoints)

- Обрабатывает входящие HTTP запросы.
- Использует Pydantic схемы (`TickerParams`) для валидации параметров.
- Вызывает соответствующие UseCase для выполнения бизнес-логики.
- Возвращает ответы в формате DTO (`CurrencyDTO`).

### UseCase слой (Сценарии использования)

- Содержит бизнес-логику приложения.
- Принимает валидированные параметры (`TickerParams`) и адаптер репозитория.
- Вызывает методы репозитория для получения или сохранения данных.
- Возвращает DTO объекты (`CurrencyDTO`) или список DTO.

### Репозиторий (Абстракция данных)

- Определяет интерфейс для работы с данными (`CurrencyDBRepository`).
- Содержит методы: `get_all_by_ticker`, `get_last_price`, `create_data`.
- Абстрагирует бизнес-логику от конкретной реализации базы данных.

### Адаптер репозитория (Реализация)

- `CurrencyDBAdapter` — конкретная реализация репозитория.
- Работает с SQLAlchemy ORM моделью `Currency`.
- Управляет сессиями базы данных (создание, закрытие).
- Конвертирует между ORM моделями и DTO.
- Выполняет фильтрацию по дате, преобразуя `date` в диапазон timestamp.

### Модели данных (Схемы)

- `CurrencyEntity` — бизнес-сущность (валидация, доменная логика).
- `TickerParams` — параметры запроса с валидацией (проверка допустимых тикеров).
- `CurrencyDTO` — объект для передачи данных в API ответе.
- `Currency` — ORM модель для работы с базой данных.

### Фоновые задачи (Celery)

- `fetch_bitcoin_price` и `fetch_ethereum_price` — периодические задачи.
- Получают данные от внешнего API Deribit.
- Создают сущности `CurrencyEntity` и сохраняют их через адаптер репозитория.
- Автоматически повторяют попытки при ошибках.
